# District Recruitment Subpage — Reusable Audit and Developer Template

Use this for a focused page under `/districts/{district}/{topic}`. Replace all bracketed values using verified route/data details. Keep this as a working checklist; do not record an item as passed without evidence.

## Page identity and baseline

- [ ] Exact route: `/districts/{district-slug}/{topic-slug}`.
- [ ] District and recruitment topic confirmed from the route and source records.
- [ ] Current rendered page, route component, shared template, data model and metadata source inspected.
- [ ] Existing content, sections, job records, navigation, links, functionality and current index policy recorded before edits.
- [ ] Screenshot/Search Console evidence tied to this exact URL is distinguished from sitewide report totals.
- [ ] Data sources, official authority and recruitment cycle identified.

## Page-specific content checklist

- [ ] Breadcrumb and one clear H1 match the actual district/topic.
- [ ] Intro tells candidates what they can find and clarifies district versus state-level coverage.
- [ ] Current status panel uses real records; empty, loading, error, active and expired states are useful and distinct.
- [ ] Listings include verified authority, location, dates, status and official links where available.
- [ ] Historical notices, corrigenda, results and waiting lists are labeled by year and type; they are not presented as open applications.
- [ ] Eligibility, age, qualification, fees, salary, selection and documents are qualified and tied to the applicable notice.
- [ ] Topic-specific explanatory sections are accurate, useful and not duplicated boilerplate.
- [ ] Related district, state, topic and preparation links resolve and serve a clear next step.
- [ ] FAQs answer real questions, have direct answers and match visible page content.
- [ ] Trust/official source statement is visible; dates and last-verified labels are data-backed.
- [ ] Existing useful page content has not been removed or overwritten.

## SEO, GEO, AEO and indexing

- [ ] Title, description, canonical, robots directives, Open Graph and H1 are unique and accurate for this exact route.
- [ ] Indexability decision is based on page value and site policy, not an assumption that every URL must be indexed.
- [ ] Rendered HTML meta robots and HTTP `X-Robots-Tag` are checked separately.
- [ ] Sitemap inclusion, canonical, status code and Search Console URL Inspection are checked for this URL when access exists.
- [ ] Keyword ideas are natural and labeled unverified until supported by Search Console/research data.
- [ ] Location refers to actual job coverage/posting, not examination-center location.
- [ ] Schema matches visible facts and appropriate page type; no fabricated `JobPosting` data.
- [ ] Direct answers and official sources are crawlable and visible; no hidden keyword copy.

## UI, accessibility and responsive behavior

- [ ] Use existing design tokens and installed icon library; add no unnecessary dependencies.
- [ ] Status panel, quick navigation, cards, tables and FAQ controls remain useful at mobile, tablet and desktop sizes.
- [ ] Buttons, links and accordions have semantic controls, accessible names, keyboard support and focus states.
- [ ] Status is not conveyed by color alone; text wraps and no unintended overflow occurs.
- [ ] Existing global header, footer and navigation remain intact.

## Pass 1 — Implementation review

- [ ] Implement the page using verified data and existing project patterns.
- [ ] Complete all page-specific content, data, metadata, links, schema and empty/error states.
- [ ] Check source accuracy and preserve existing functionality.
- [ ] Run applicable lint, type, test and build scripts; record exact outcomes.
- [ ] Record code/data changes, evidence and unresolved dependencies.

## Pass 2 — Independent verification

- [ ] Reopen the exact rendered route and verify all sections, facts and status states.
- [ ] Verify the URL's actual robots meta, HTTP header, canonical, status and sitemap policy.
- [ ] Recheck every internal/external destination and source date.
- [ ] Test mobile/tablet/desktop, keyboard, FAQ controls, links and all relevant loading/empty/error/active/expired states.
- [ ] Review console/network output and check that unrelated district routes still work.
- [ ] Record proof for each pass/fail/blocked/untested item; leave unresolved issues open.
